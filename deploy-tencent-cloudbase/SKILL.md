# CloudBase 部署

把应用发布到用户指定的 CloudBase 环境，交付可访问地址和实际运行证据。构建成功、版本正常、承接流量、业务可用是不同状态，分别确认。

## 工具选择

默认使用官方 `@cloudbase/cli`（`tcb`）完成资源查询与发布，浏览器用于登录授权、CLI 不支持的控制台操作和页面验收。用户明确指定操作方式时优先遵从。先运行 `tcb -v` 和目标子命令的 `--help`；未安装时再安装，不为部署例行升级。CLI 流程及命令选择见 [references/cli-deployment.md](references/cli-deployment.md)。

- 静态网站需要应用版本记录：使用 `tcb app deploy`。仅上传静态文件、不需要应用版本管理时才使用 `tcb hosting deploy`。
- 容器或函数型云托管服务：使用与当前环境匹配的 `tcb cloudrun deploy`；不要混用其他代际产品的 `tcb run service:deploy`。
- 先只读验证现有登录；成功后直接复用，无需重复登录或再次索要密钥。CLI 失败先定位权限、环境、参数或网络问题，再决定是否回退控制台。

## 定位目标与授权

- 先读项目运行方式、已有部署配置与用户约束。纯静态页面与需要后端/长连接/自定义运行时的应用分开选择托管产品；不要为了套流程把静态站改成容器服务。
- 核对当前账号登录、环境/地域、套餐有效期、现有服务与业务。优先复用合适资源，更新明确指定的服务；不同项目不要覆盖原站点。目标身份不唯一时先只读定位。
- 尊重用户指定的浏览器、窗口和 Tab。指定现有 Chrome 第一 Tab 时，在那个会话操作；工具连接的另一浏览器或空白页不能替代。会话不可用、锁屏或登录挑战时，说明具体障碍并让用户处理，不开新会话绕过。
- 已有部署授权覆盖约定服务的必要发布与切流，不能据此删除资源、扩大公网访问、迁移数据库或购买新套餐。查看当前操作影响后，只对缺少授权的具体变更提问。
- 云托管启用涉及服务条款时，交用户阅读、接受并提交。新订单、充值、实名认证或认证挑战交用户处理，说明页面所需信息与可见金额；金额未显示时不要猜或宣称免费。账户有余额/体验额度不等于所有后续操作免费。

## 准备可运行的发布物

- 静态项目先确认部署根路径或子路径，构建资源前缀与云端挂载路径一致。发布到独立目录，避免共享 `dist/` 在上传期间被开发或其他构建改写；按发布目录生成文件清单与指纹。仅上传构建产物，保留应用必需的 Workers、字体、数据等资源。
- 保持项目技术栈，完成必要的构建与相关测试。容器部署核对 Linux、CPU 架构、运行时和依赖兼容；macOS 专用库或本机路径不能直接移入 Linux 镜像。例如含 MLX 的本地推理需验证 Linux 替代实现，而非仅替换包名。
- 打包实际需要的源码、锁文件和 Dockerfile，或上传已经验证的镜像；使用明确构建上下文。检查压缩包目录及 Docker COPY 来源。`.dockerignore` 不会自动保护上传的 ZIP，应单独检查包清单。
- 排除密钥、环境文件、证书私钥、虚拟环境、测试录音及其他非发布资料。运行时秘密通过平台环境变量/适用秘密机制注入，不能放在前端、镜像层、构建参数、截图或日志中。构建阶段与运行时变量不同，不能假设服务环境变量在 Docker RUN 时已存在。
- 容器监听可访问接口（通常为 `0.0.0.0`），进程真实端口与平台配置一致。验证启动命令、无守护进程退出问题和健康检查；有代理终止 HTTPS 时检查同源校验、受信代理范围和 Secure Cookie。
- 按工作负载选择资源和实例数，不固定规格、地域、端口或最小副本数。对缩至0与常驻实例分别解释冷启动和持续费用；新增长期付费选择在授权范围不明确时交用户决定。

## 发布与切流

优先执行已核对参数的 CLI 命令，显式指定环境、应用/服务和发布目录。不要默认加入 `--force` 或 `--yes`；在已有授权范围内核对交互确认的目标后继续，无需把同一部署授权重复交回用户。需要控制台回退时读 [references/console-and-troubleshooting.md](references/console-and-troubleshooting.md)。

记录目标服务、版本/任务标识与发布物来源。观察状态和日志采用有界等待：未改变时拉长检查间隔，保持进度沟通；达到选定截止时间后读取任务/构建/启动日志并报告待处理状态，不能因此重建相同项目或称已上线。失败时依据具体错误修复，再进行有范围的重试。

静态托管以应用版本状态、公网资源内容一致和业务验收判断生效，不套用容器版本的100%流量标准；共享环境发布前后比较原站点入口指纹，确认仅更新目标子路径。

云托管新版本就绪后检查实际流量配置。正常但未承接流量时，在授权范围内使用当前产品的切流入口；界面可能通过发布、流量设置或切换/回退版本完成，先读确认框里的当前和目标版本，再提交。灰度需求按约定分配，完整替换才确认目标100%。不要仅凭“自动切流”选项认定已生效。

## 公网验收与交付

切流后通过最终 URL 验证本次变更和完整业务路径，必要时比较构建资源指纹/版本标识；按 [references/verification.md](references/verification.md) 区分接口、浏览器、媒体、真机和冷启动证据。

默认域名只作为开发测试入口。遇到平台访问提示中间页或附件响应头，先辨别响应来自平台还是应用；正式服务按当前要求使用已完成备案的自定义域名。不得伪造请求头规避域名限制，也不能代用户绕过浏览器证书安全警告。

不要自动添加用户未要求的访问认证。确需认证时保持既有授权约束，移动端普通网页登录应验证输入表单与会话，不能只验 HTTP Basic 的桌面原生框。

交付最终 URL、版本/流量状态、真实业务结果、测试条件与剩余限制。未验证的手机权限、冷启动或时延目标明确标注；用户协助仅针对无法代测或无法继续的具体事项。部署完成后停止无必要的探测和改动。
